How prediction markets work

A prediction market lets you trade on the outcome of a real-world event — "will X happen by date Y?" Every market has two sides, Yes and No, each priced between 1¢ and 99¢.

A price is a probability. If Yes is trading at 62¢, the market thinks there's roughly a 62% chance the event happens — that's what "implied probability" means: just the price, read as a percent chance instead of a dollar amount.

Yes + No always add up to about 100¢ because they're two sides of the same bet — if something is nearly certain to happen, Yes trades near 99¢ and No trades near 1¢, and vice versa.

Settlement is what happens once the real-world event is actually decided: the market "settles," and every contract on the correct side pays out $1, every contract on the wrong side pays out $0. There's no partial credit — a position's value is whatever you paid for it until the moment it settles to either $1 or $0.

Position Management (Exits) — selling before settlement

Kalshi lets you sell before settlement instead of only holding to $1/$0 - these actively manage positions already opened, closing them at the current market price instead of leaving every trade to sit untouched until resolution. All off by default.

A fourth, independent layer on top of the hard rules above: blends unrealized P&L magnitude, whale-sentiment reversal strength, and how long whale interest in this ticker has gone quiet into one 0–1 "exit confidence" score, the same mental model signal.confidence already uses on the entry side. Market-Native Strategy 🆕 new — a second, whale-independent paper strategy

A second, fully independent automated paper-trading strategy, off by default - trades purely on real Kalshi market data (price, spread, volume, momentum), no whale signal input at all. Its own bankroll and trade log (see GET /api/market-strategy/state), so it never mixes with the whale-follow account above. Exists to start building a real, whale-independent trade-history dataset now, while the whale feed is still simulated - see docs/advisory-engine-plan.md. No dashboard panel yet (backend-only for now); this is the only place to configure or enable it.

Market Analyst (AI) 🆕 new — an LLM forms its own probability estimate per market

A third, genuinely different kind of strategy input alongside whale-flow and momentum above - instead of arithmetic factor scoring, an LLM reads a market's actual title, rules, and this app's own accumulated track record, then forms its own probability estimate. On-demand only: click "Analyze" on a market's detail view to spend a real API call on it (see the Market Analyst panel on the Trading History tab for past results) - nothing runs automatically in the background, since this is the only strategy input in this app that costs real money per use. Off by default, and needs an ANTHROPIC_API_KEY set in .env too - both are required. Once a market's been analyzed, its lean quietly feeds the cheap, arithmetic whale confidence score too (the new "analyst" factor - neutral until a fresh analysis exists, no extra API cost to use it there). Still fully advisory: nothing here ever places a trade or writes config on its own.

Whale Signal (simulator) 🧪 sim data — fallback only, the real provider below is active by default

Governs the built-in simulator only. Since the real Kalshi Trade Tape provider below needs no setup and is active by default, the fields below now only matter as a fallback (used automatically for one tick if the real provider's fetch fails) or if you deliberately switch back to simulator-only mode (WHALE_WATCHER_PROVIDER=generic_rest with no WHALE_WATCHER_API_URL, in .env, plus a restart).

Whale Signal (real — Kalshi Trade Tape) — size-based, from the real public trade feed, active by default

Kalshi has no public trader identity or leaderboard, so this is strictly size-based: any real trade on the exchange whose dollar size clears the threshold below becomes a whale signal, scored the same way the simulator's confidence is. Active by default (needs no setup) — set WHALE_WATCHER_PROVIDER in .env to something else, plus a restart (ddev restart), to turn it off instead.

Series Evaluator 🆕 new — is a series even worth watching for whale signals?

The watchlist is fully recomputed every tick with no memory of past ticks, so a series near a volume/live-status cutoff can flap in and out repeatedly. When enabled, a newly admitted series is observed for a while, then judged on the real fraction of its trades that actually clear the whale-notional threshold above. A series that fails gets backed off from re-admission for an escalating period (doubling each repeated failure); approval is sticky and never silently revoked. See the History tab's Series Evaluator panel for the full log, including a manual re-evaluate action. Off by default - trades are still recorded either way, so there's real history to act on the moment this is turned on. All the numeric defaults below are placeholders, not yet retuned against real data.

Market Discovery — the automatic watchlist

Governs the automatic watchlist only (used when no markets are pinned below). Pinned markets always show regardless of these thresholds.

Checks live status across the full candidate pool before picking the watchlist, not just after - costs more per tick (more markets checked), and the watchlist can end up smaller than the size above (down to zero) rather than getting padded with non-live markets to hit that number.

The watchlist size above now counts distinct parent series (the top-most level of Kalshi's own Series → Event → Market hierarchy that still represents one market — e.g. "PGA Head-to-Head Matchups", which covers a whole tournament like Wyndham Championship), not individual markets — once a series is selected, every event and market under it is watched by default, highest-volume first. A tournament with 20+ live pairings costs exactly one watchlist slot. Set a cap here if one very active series is crowding out watchlist variety you'd rather keep.
