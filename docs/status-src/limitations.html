Known Limitations

Every currently open Kalshi market is a multi-leg combo contract
Verified by paginating 500 live open markets from Kalshi's real API — zero simple single-outcome markets exist right now. Titles are formatted as "N-leg parlay: A, B +N more" to stay scannable, but that's the ceiling on readability given the actual data, not a partial fix.
Order-placement request schema was wrong — now fixed (verified 2026-08-07)
This used to be an open question; it turned out the original implementation targeted Kalshi's legacy order shape (POST /portfolio/orders, integer-cents yes_price/ no_price). Fetched docs.kalshi.com directly and found the endpoint moved to POST /portfolio/events/orders, with action+side(yes/no) collapsed into one side field ("bid"/"ask"), string-typed count/price instead of integer cents, and two newly-required fields (time_in_force, self_trade_prevention_type) with no old equivalent. Kalshi's own docs note the legacy endpoint's migration deadline was "no earlier than May 6, 2026" — already past — so the old code could have failed outright the first time it was ever used. Rewritten and covered by 4 tests that verify the exact request shape against a faked HTTP client (no network, no real credentials). Still true: no live order has ever actually been placed with this code, and Kalshi's docs can move again — don't treat this as a permanent guarantee.
No "close position" flow
The paper broker opens positions but nothing ever explicitly closes one — equity reflects mark-to-market unrealized P&L on whatever's still open. There's no realized-P&L concept yet, so none is shown.
Real account connection: verified 2026-08-07, and the auth signing itself was broken
A real key made it possible to test this for the first time, and it surfaced a genuine bug, not just an unconfirmed guess: every signed request 401'd, on both production and demo — the signed message omitted the /trade-api/v2 prefix Kalshi's own docs example includes. Fixed in services/kalshi_account_client.py. Once auth worked, several field-name guesses turned out wrong too — market_positions uses position_fp/market_exposure_dollars, fills use count_fp/yes_price_dollars/no_price_dollars — none of which existed under the old guessed names, so those rows silently rendered blank before. All fixed and verified against a real connected account in a real browser session. Raw JSON stays visible everywhere regardless, since Kalshi's docs can still drift again — this is now confirmed-correct, not guaranteed permanent.
